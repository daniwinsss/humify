# Humify Founder Demo Script

This script is written for a 8-12 minute product walkthrough video for the founder.
It is designed to sound confident, product-focused, and easy to follow during a live screen recording.

---

## 1. Opening Hook

**On screen:** Humify landing page

**Say:**

"Hi, this is Humify, an AI text humanizer built to take machine-written content and make it sound natural, readable, and genuinely human while preserving the original meaning.

What makes Humify different is that it is not just a one-click rewrite tool. It gives the user control over style, language, tone, formality, and even custom writing profiles. It also includes writing analysis, document preservation for HTML and DOCX, rewrite history, feedback learning, API access, and operational metrics.

In this walkthrough, I’ll show you how the product works end to end, why the architecture was designed this way, and what makes the text-humification pipeline reliable enough for real use."

---

## 2. Problem Statement

**On screen:** Still on landing page, scroll slowly through the hero and how-it-works section

**Say:**

"The core problem Humify solves is that AI-generated writing often sounds robotic, repetitive, or overly formal. Many humanizers can rewrite text, but they usually do not give much control, they can drift away from the original meaning, and they often provide no visibility into what changed.

Humify was designed to solve those problems by combining three things:

1. Prompt-driven humanization with controlled style output.
2. Analysis of the original and rewritten text.
3. Preservation of formatting and structure for documents.

So the product is not just about making text sound more human. It is about making it controllable, inspectable, and safe to use."

---

## 3. Quick Product Tour

**On screen:** Click into the main app

**Say:**

"Inside the app, the workflow is intentionally simple.

The user can start in text mode for plain rewrite tasks, or switch to document mode for HTML, DOCX, and plain text files. The interface also supports style presets, custom profiles, language selection, rewrite history, and an analysis dashboard.

I’ll start with text mode first, because that shows the main intelligence layer of the product."

---

## 4. Text Humanization Flow

**On screen:** Paste a sample AI-like paragraph into the text box

**Say:**

"Here I’m pasting in a piece of text that feels synthetic or too stiff. The point is to show how Humify reshapes it without losing the meaning.

Before rewriting, I can choose a style preset. The available options are Professional, Casual, Academic, and Friendly.

Each preset is mapped to a different prompt instruction:

- Professional keeps the language polished and business-like.
- Casual makes the output more conversational.
- Academic keeps structure and precision for scholarly writing.
- Friendly makes the tone warmer and more approachable.

This matters because a lot of text tools only offer one generic rewrite button. Humify gives the user a voice choice, which is a much more realistic product experience."

**Action:** Select one style, then click Analyze first

**Say:**

"I usually start with analysis because it gives me a baseline before I rewrite.

The analysis endpoint evaluates readability, formality, sentence complexity, emotional tone, and suggestions. That gives the user feedback on why the text feels robotic in the first place, not just what the final rewrite looks like."

---

## 5. Writing Analysis

**On screen:** Show the analysis dashboard for the original text

**Say:**

"This analysis is generated by Gemini using a structured JSON response. The app asks the model to return:

- a readability score and grade level,
- a formality score,
- a sentence complexity score,
- an emotional profile,
- and a set of actionable suggestions.

That means the analysis is not just a visual decoration. It is a real interpretation of the text, and it helps explain to the user what is making the writing feel unnatural.

For example, if the readability is high but the tone is too formal or the sentences are too dense, the rewrite can be guided accordingly."

**Optional line if you want to sound more technical:**

"The dashboard also compares original versus rewritten scores, which helps show whether the rewrite actually improved the text rather than just changing its wording."

---

## 6. Rewrite Demo

**On screen:** Trigger Humanize Text

**Say:**

"Now I’ll rewrite the same text.

Under the hood, the app composes a system prompt from the selected style, the selected language, and optionally a custom writing profile. If the user has positive feedback history for that style, Humify also injects a few previously liked examples into the prompt so future rewrites can better match user preference.

That feedback loop is important because it makes the system more personal over time without needing a full training pipeline.

When I submit the rewrite, the app sends the request to Gemini, saves the result into SQLite, and then immediately runs analysis on both the original and rewritten versions so the user can compare them side by side."

**On screen:** Let the result load

**Say:**

"The key design principle here is meaning preservation. The model is instructed to sound human, but not to invent new facts or change the intent. That keeps the output useful for real work instead of turning it into an uncontrolled paraphraser."

---

## 7. Compare Original and Humanized Output

**On screen:** Show the side-by-side result view

**Say:**

"Now we can compare the original and the humanized version side by side.

This is useful for trust. The user is not forced to blindly accept the rewrite. They can inspect the change, compare word counts, and decide whether the output preserved the original meaning.

The app also stores the rewrite in history so the user can come back to it later, restore it, or review past output."

**Optional line:**

"This turns the product from a disposable one-off AI tool into something closer to a working writing system."

---

## 8. Feedback Learning

**On screen:** Click thumbs up or thumbs down on a rewrite

**Say:**

"Humify also includes feedback learning.

If a user likes a rewrite, that feedback is stored in SQLite and future rewrites for the same style can use those positive examples as reference. If they dislike a result, that is tracked too.

This is a lightweight personalization layer. It is not full model training, but it is a practical way to shape output based on what the user actually wants."

---

## 9. Writing Profiles

**On screen:** Open profile manager and show creating a custom profile

**Say:**

"Another important feature is custom writing profiles.

Instead of relying only on the built-in styles, the user can create a profile with:

- a name,
- a tone,
- a formality level,
- and custom instructions.

For example, someone might create a profile for blog writing, investor updates, customer emails, or founder updates.

This matters because real users often want repeatable voice control. A team member should be able to say, 'Use my brand voice,' instead of re-selecting the same tone every time."

---

## 10. Language Support

**On screen:** Change output language dropdown

**Say:**

"Humify supports multiple languages as well. The prompt can either keep the output in the same language as the input, or switch to a specific output language.

That means the product is not only humanizing English text. It can also help with cross-language rewriting, which makes it much more useful for global teams and multilingual content workflows."

---

## 11. History and Persistence

**On screen:** Open history panel

**Say:**

"Every rewrite is stored in the local SQLite database.

The history panel gives the user a persistent record of previous rewrites, which is useful for iteration, review, and recovery. If someone wants to go back to a previous result, they can restore it instantly.

This is a small feature, but it makes the product feel like a real application instead of a temporary AI demo."

---

## 12. Document Humanization

**On screen:** Switch to document mode

**Say:**

"Document mode is one of the most technically interesting parts of Humify.

The app supports HTML, DOCX, and TXT input. The goal is to humanize the text while preserving as much formatting and structure as possible.

This is much harder than rewriting plain text, because the app has to avoid breaking paragraphs, links, tables, headings, inline formatting, and non-text regions like code or script blocks."

**Action:** Upload a sample DOCX or HTML file

**Say:**

"When a file is uploaded, the pipeline does four things:

1. Parses the document structure.
2. Extracts only humanizable text blocks.
3. Rewrites those blocks through Gemini using a special formatting protocol.
4. Rebuilds the file and generates a preservation report.

That preservation report is a major trust feature because it verifies what actually survived the round trip instead of assuming the structure is intact."

---

## 13. Document Preservation Logic

**On screen:** Show report and preview

**Say:**

"For HTML, the app keeps the DOM structure and skips elements like scripts, styles, code, preformatted text, and other non-prose blocks.

For DOCX, it walks the underlying XML structure, preserves runs and paragraph boundaries, and avoids rewriting things like Word field codes that are meant to be regenerated by Word itself.

The document pipeline also batches text into chunks so the app does not waste API calls one tiny fragment at a time. If a batch comes back malformed, it falls back to smaller retries, and if necessary it keeps the original content rather than corrupting the file.

That is important because the product is not just trying to make text sound good. It is trying to avoid damaging the source document."

**Optional line:**

"The report is generated from the actual output file after re-parsing it, which makes the preservation metrics more trustworthy."

---

## 14. Output and Download

**On screen:** Show download button and preview toggle

**Say:**

"After processing, the user can download the rewritten file in the correct format, or plain text if they choose a lossy fallback.

For HTML and DOCX, the app also gives a browser preview so the user can quickly inspect the result without opening another app.

This makes the document flow feel complete: upload, humanize, verify, and download."

---

## 15. API Access

**On screen:** Open settings page, API section

**Say:**

"Humify also exposes a REST API.

There is a protected rewrite endpoint that accepts a bearer API key, which means developers can integrate this into their own tools or internal workflows.

That is important because it turns Humify from a standalone UI into a reusable service. The same rewrite engine can power a website, a content tool, or an internal assistant."

**Optional line:**

"The app also tracks metrics like request counts, latency, error rates, and style usage, so the service can be monitored as it grows."

---

## 16. Why the Architecture Matters

**On screen:** Return to main app or open a neutral state

**Say:**

"From an architecture standpoint, the product is intentionally modular.

The UI is separate from the prompt-building layer, the Gemini wrapper is separate from the document pipeline, and the persistence layer is isolated in SQLite.

That structure makes the system easier to extend. For example, if we want to add another model provider, improve the analysis schema, or introduce team workspaces later, those changes can be made without rewriting the entire app."

---

## 17. Founder-Focused Summary

**On screen:** End on polished app view

**Say:**

"So the short version is this:

Humify is not just a text rewriter. It is a controlled humanization platform with style selection, custom profiles, structured analysis, document preservation, feedback-based improvement, and developer-facing API access.

The main value is that it combines quality, control, and reliability in one workflow.

The result is a product that feels practical for real users, not just impressive in a demo.

That is the system I wanted to show you today."
